# Promptbanken Open 1.3.0 – MCP Apps-widgets och Superplan-skill

Datum: 2026-09-26
Status: Godkänd design, väntar på implementationsplan
Gren: `open-1.3.0-apps`

## Syfte

Ge Promptbanken Open ett grafiskt gränssnitt i ChatGPT (och andra MCP Apps-värdar
som Claude) för de delar av katalogen där text fungerar dåligt, och paketera
Superplanläge som en skill som kan ingå i OpenAI-plugin-inskickningen.

Kartläggning av katalogen 2026-09-26 (35 paket, varav 16 workflows med 4–10
ordnade steg; rollen `chef` får 18 rekommenderade paket) visade att värdet är
störst för workflows och rollrekommendationer, och lågt för formulär
(`parameter_schema` är `null`, mallarna är designade som samtal).

## Bakgrund: plattformsläget

- **MCP Apps** (SEP-1865, tillägg `io.modelcontextprotocol/ui`, stabil version
  2026-01-26) är officiell MCP-standard. ChatGPT, Claude, VS Code och Goose
  stöder den.
- Standard: `_meta.ui.resourceUri` på verktyg, `ui://`-resurser med
  `mimeType: text/html;profile=mcp-app`, resurs-`_meta.ui`
  (`csp`, `domain`, `prefersBorder`), verktygs-`_meta.ui.visibility`, och
  JSON-RPC-bryggan över `postMessage` (`ui/initialize`,
  `ui/notifications/tool-input`, `ui/notifications/tool-result`, `tools/call`,
  `ui/message`, `ui/update-model-context`).
- ChatGPT-tillägg (`window.openai`: `requestDisplayMode`, `widgetState`,
  `requestModal` m.fl.) används endast via feature detection.
- Legacy-nycklar (`openai/outputTemplate`, `openai/widgetCSP`,
  `openai/widgetDomain`, `openai/widgetAccessible`, `openai/visibility`,
  `openai/widgetPrefersBorder`) används inte.
- OpenAI-plugins kan kombinera remote MCP och skills. Skills laddas upp som
  bundle vid inskickning och blir en ögonblicksbild; ändringar av skill eller
  verktygsdefinitioner kräver ny version och granskning.

## Beslut

| Fråga | Beslut |
|---|---|
| Skilltyp | Agent Skill (`SKILL.md` + `agents/openai.yaml`), uppladdad som bundle |
| Framsteg i workflows | Endast i chatten; ingen serverlagring, ingen identitet |
| Paketkortens grafik | Genereras från `package_type`/`area`; `icon_key`/`color_theme` används när de finns |
| `search_templates.area` | Blir öppen sträng i stället för enum |
| Widgetteknik | Ren HTML/JS, en fil per widget, inget byggsteg, egen standardbrygga |
| Navigering i widgets | `ui/message` (modellen ser och styr), inte `tools/call` |
| Superplan och stegvisare | Superplan visar inga faser (mallarnas krav); stegvisaren används för workflows som Superplan routar till |

## 1. Arkitektur

### Nya filer

- `mcp-server/widgets/bridge.js` – standardbrygga för MCP Apps med
  `window.openai` som valfritt tillägg.
- `mcp-server/widgets/package-cards.html`
- `mcp-server/widgets/workflow-stepper.html`
- `mcp-server/widgets/template-view.html`
- `mcp-server/widgets/dev-harness.html` – lokal testvärd, serveras inte.
- `mcp-server/server/widgets.py` – resursregister; läser widgetfilerna vid
  start, bakar in `bridge.js`, cachar i minnet.

### Ändringar i `/mcp` (`_handle_mcp_message`, endast public-profilen)

- `initialize` annonserar `capabilities.resources`.
- Nya metoder `resources/list` och `resources/read` för
  `ui://promptbanken/package-cards.html`, `ui://promptbanken/workflow-stepper.html`
  och `ui://promptbanken/template-view.html`, med
  `mimeType: text/html;profile=mcp-app` och `_meta.ui`:
  `prefersBorder: true`, `csp` med tomma listor (allt inbäddat), `domain`.
- `/sse` (FastMCP) och `key_authenticated`-profilen ändras inte.

### Koppling verktyg → widget (`_meta.ui.resourceUri`)

| Verktyg | Widget |
|---|---|
| `recommend_packages`, `list_packages` | paketkort |
| `list_package_prompts` | stegvisare (workflow) / lista (collection) |
| `get_template` | mallvy |
| `get_package`, `search_templates`, `list_templates`, `health_check`, `get_client_routing_instructions` | ingen widget |

`get_package` returnerar inga steg och får därför ingen widget; stegvisaren
ritas från `list_package_prompts`.

### Kontraktsändringar (1.3.0)

- `recommend_packages` returnerar per paket även `title`, `summary`,
  `package_type`, `audience_label`, `icon_key`, `color_theme` (hämtas från
  samma katalogdata som `list_packages`; ingen databasändring).
- `search_templates.area`: öppen sträng. Okänt värde ger tomt resultat med en
  hint om att giltiga värden finns via `list_packages`.
- `list_package_prompts` får valfritt argument `current_step` (heltal ≥ 1 och
  ≤ antal steg). Värdet ekas i `structuredContent`; ingen lagring. Ogiltigt
  värde ger tydligt fel.
- `list_package_prompts` returnerar även ett `package`-objekt (`slug`, `title`,
  `package_type`, `summary`, `icon_key`, `color_theme`) så stegvisaren kan
  skilja workflow från collection utan extra anrop.
- Textsvar och övrig `structuredContent` oförändrade; klienter utan UI
  påverkas inte.
- Nytt kontrakt `mcp-server/contracts/promptbanken-open-1.3.0.tools.json`.
- `SERVICE_VERSION` → `1.3.0`.

### Dev-miljö

Nuläge (verifierat 2026-09-26): prod- och dev-containern byggs båda från
`~/mcp_promptbanken` på `main` och pekar båda på prod-Supabase
(`cohyrgxeatqexkqihktu`). Dev skriver därmed användningshändelser
(`track_library_usage_event`) till prod.

Ny dev-miljö:

- Separat klon `~/mcp_promptbanken_dev` på grenen `open-1.3.0-apps`, eget
  compose-projekt, en tjänst med `container_name: promptbanken-open-dev-mcp`
  på `127.0.0.1:8001`.
- Egen `.env` mot dev-Supabase (`dklxriwjskyglqeombvv`). Användaren fyller i
  nycklarna själv på VPS:en; hemligheter passerar aldrig chatten.
- Admin-styrning: i `~/promptbanken-admin-control/admin_control.py` ändras
  `SERVICES["mcp-dev"]` till `"promptbanken-open-dev-mcp"`, följt av
  `systemctl --user restart admin-control`. Admin-gränssnittet ändras inte.
- Ordning: bygg och verifiera ny container → byt mappningen → testa
  start/stop/status från admin → ta bort gamla
  `mcp_promptbanken_promptbanken-mcp-dev_1`. Återställ mappningen om något
  fallerar.
- Caddy ändras inte (`mcp-dev.promptbanken.se` → `127.0.0.1:8001`).
- Prodkatalog, prod-container och prod-databas rörs inte.
- Förutsättning: dev-Supabase har katalog-RPC:erna och publicerat innehåll.
  Om inte krävs först en katalogsynk prod → dev (eget deljobb).

## 2. Widgets

### Gemensamt

- Bryggan skickar `ui/initialize`, läser tema/språk från `hostContext`, tar
  emot `ui/notifications/tool-result`, skickar `ui/message` och
  `ui/update-model-context`.
- All katalogtext sätts med `textContent`; aldrig `innerHTML`, `eval` eller
  externa URL:er.
- Svenska, ljust/mörkt tema, mobilbredd, tangentbord och `aria`-etiketter,
  under 30 KB per widget.
- Grafik: ikon efter `package_type`, färg efter `area`; `icon_key`/`color_theme`
  används när de finns.

### Paketkort

- Karusell: typmärke, titel, sammanfattning, antal steg/mallar, målgrupp.
- Filter Alla / Arbetsflöden / Samlingar, lokalt i widgeten.
- "Öppna" → `ui/message` "Visa paketet <titel>".

### Stegvisare

- Workflow: numrerad steglista med `step_title`/`step_intro`; klarmarkerade,
  aktuellt och kommande steg. Aktuellt steg från `current_step`; i ChatGPT
  sparas klickade steg även i `widgetState`.
- "Starta steg N" → `ui/message`. "Helskärm" visas bara om värden stöder det.
- Collection: enkel lista utan ordning eller status.
- Verklighetsstopp visas inte (datafält saknas); hanteras av skill/mall.

### Mallvy

- Titel, syfte, risknivå som märke, `security_examples` i synlig ruta överst.
- Prompttext ihopfälld som standard.
- "Använd mallen" → `ui/message`.

### Felhantering

- Saknad eller felformad `structuredContent` → "Kunde inte visa innehållet";
  textsvaret gäller.
- Inget svar på `ui/initialize` inom ca 2 s → `window.openai.toolOutput` om
  det finns, annars neutralt meddelande.
- Saknad värdfunktion → knappen döljs.

## 3. Superplan-skill

### Princip

Tunn dirigent. Skillen innehåller inga prompttexter från katalogen; den hämtar
Superplans fyra faser live via MCP. Katalogen förblir enda källan och kan
redigeras via Admin-MCP utan att skillens ögonblicksbild blir inaktuell.

### Filer

```
plugin/
  <plugin-manifest enligt OpenAI:s paketeringsformat>
  skills/superplan/
    SKILL.md
    agents/openai.yaml
  evals/superplan-cases.md
```

`agents/openai.yaml` deklarerar beroende på Promptbanken-MCP
(`streamable_http`): `https://mcp-dev.promptbanken.se/mcp` under utveckling,
`https://mcp.promptbanken.se/mcp` vid utgivning.

### Innehåll i SKILL.md

- **Aktivering:** användaren vill ta en idé eller ett uppdrag hela vägen till
  ett färdigt, kontrollerat resultat ("kör superplan", "hjälp mig hela vägen",
  komplext uppdrag utan tydlig väg).
- **Flöde:** `list_package_prompts("superplanlage")` en gång; `get_template(id)`
  för varje fas när den nås; följ fasens instruktion. Faser: riktning,
  specifikation, utförande och routing, verifiering.
- **Osynlig process:** inga fasnamn och ingen stegvisare för Superplan självt.
- **Routing:** `search_templates` med anonymiserade söktermer,
  rekommendera ett alternativ först; högst tre jämnstarka visas med
  paketkorten. Är specialisten ett workflow används stegvisaren
  (`list_package_prompts` med `current_step`).
- **Integritet:** aldrig användarens text, dokument eller personuppgifter till
  katalogsökning; användarens innehåll kombineras med mallen endast lokalt.
- **Återupptagning:** i ny chatt be om senaste riktning/överenskommelse och
  fortsätt från rätt fas.
- **MCP nere:** säg det tydligt, erbjud att fortsätta utan katalogen, hitta
  aldrig på mallinnehåll.

### Testfall

Enligt OpenAI:s fem kategorier: direkt begäran, indirekt formulering,
ofullständig indata, utanför område, kantfall (återupptagning, MCP nere).
Körs manuellt i ChatGPT developer mode och Codex mot dev.

## 4. Test och utgivning

### Servertester (pytest, TDD)

- `initialize` annonserar `resources` endast i public-profilen; `/sse` och
  `key_authenticated` oförändrade.
- `resources/list`/`resources/read`: URI:er, `mimeType`, `_meta.ui`; okänd URI
  ger JSON-RPC-fel.
- `_meta.ui.resourceUri` finns på rätt verktyg och saknas på övriga.
- `current_step`: ekas; 0, negativt, för stort och fel typ ger fel; utelämnat
  ger dagens svar.
- `list_package_prompts` innehåller `package`-objektet med rätt `package_type`.
- `recommend_packages` nya fält; `search_templates.area` öppen sträng och
  okänt värde ger tomt resultat med hint.
- Kontrakt: ny snapshot för 1.3.0 låses av test; 1.2.2-filen behålls som
  historik.
- Widgetfiler: statiskt test mot `innerHTML`, `eval`, `http`-URL:er och
  storlek över 30 KB.

### Webbläsartester

`dev-harness.html` simulerar värden med fixture-data. Playwright verifierar
rendering, filter, `current_step`-markering, utgående `ui/message`,
ljust/mörkt/mobil och att fientlig katalogtext (`<script>` i titel) visas som
text.

### Dev-verifiering

1. Dev-Supabase har katalog-RPC:er och data.
2. Ny dev-container byggd; start/stop/status från admin fungerar; gammal
   container borttagen.
3. `/healthz` och strikt kontraktstest mot `mcp-dev`.
4. ChatGPT developer mode: tre widgets och skillens testkategorier.
5. Claude: samma widgets (standardkompatibilitet).
6. RAM-kontroll under körning.

### Utgivning (separat beslut)

- `chatgpt-app-submission.json`: beteendebaserade testfall (minst 5 positiva,
  3 negativa), CSP, `ui.domain`.
- `ui.domain`: OpenAI:s exakta krav och domänverifiering fastställs i
  implementationsplanen.
- Merge till `main` och prod-deploy endast efter godkänd dev-verifiering och
  uttryckligt ja. 1.2.2 ligger kvar live under OpenAI-granskningen.
