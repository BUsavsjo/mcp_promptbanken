# Promptbanken Open 1.3.0 – routing först, UI som kvittens

Datum: 2026-09-27
Status: Godkänd design, väntar på implementationsplan
Gren: `open-1.3.0-apps` (bygger vidare på `2026-09-26-open-1.3.0-apps-and-superplan-skill-design.md`)
Underlag: Peters handover efter mobiltest i ChatGPT 2026-09-27.

## Produktprincip (låst)

Promptbanken är i första hand en router för arbetssätt, inte en katalog.
Standard: **beskriv behov → automatisk routing → börja arbeta.**
UI används selektivt för att välja, förstå, orientera sig och utforska.
Kortform: *Upptäcka → rik UI. Välja → kompakt UI. Arbeta → konversation.*

## Beslut

| Fråga | Beslut |
|---|---|
| Widget för `get_template` | Alltid en kompakt aktiv-rad: `✓ {titel} · används nu`. Detaljer bara när användaren öppnar "Visa mallen". Ingen "Använd mallen"-knapp. |
| Stegvisarens läge | Styrs av anropet: `current_step` → arbetsläge (kompakt); utan `current_step` → utforska (kompakt radlista); `include_prompt_text=true` → instruktionsladdning (bara liten rubrik). Regeln "dölj steg när `step_title` saknas" tas bort. |
| Rekommendationer | Högst 5 primära, resten bakom "Visa fler (N)". |
| Mobil | Under 480 px bredd: lodrät radlista i stället för karusell. |
| Routing | Styrs via `get_client_routing_instructions` (fri text) och verktygsbeskrivningar; ingen ny routinglogik i sökningen. |

## 1. Mallvyn → aktiv-rad (`template-view.html`)

- Standardläge, alltid:
  `✓ {template.title} · används nu`
  under det en liten rad med syftet (en rad, avkortad med ellips via CSS).
- En knapp/disclosure **"Visa mallen"** (`<details>`) fäller ut: risknivå-märke,
  säkerhetsråd (om `security_examples` finns), prompttext (`<pre>` med
  `aria-label="Prompttext"`).
- Inget område-märke (arbetsflödeskontext går före katalogmetadata; se §5).
- Ingen "Använd mallen"-knapp. Att modellen hämtar mallen betyder att den används.
- Felläge: `status: error` → "Mallen hittades inte."
- Samma widget renderad igen för samma mall ger samma kompakta rad (inga stora
  dubblettkort).

## 2. Stegvisaren → tre lägen (`workflow-stepper.html`)

Läget avgörs av `structuredContent`:

1. **Instruktionsladdning** – något steg har `prompt_text` (anropet gjordes med
   `include_prompt_text=true`, t.ex. Superplan-skillen): visa endast en liten
   rubrik `{package.title}` utan steglista och utan knappar.
2. **Arbetsläge** – `current_step` är ett heltal och paketet är ett arbetsflöde:
   ```
   {package.title}
   Steg {X} av {Y}
   {aktuellt stegs etikett}
   Nästa: {nästa stegs etikett}        (utelämnas på sista steget)
   [Visa alla steg]                     (disclosure → kompakt radlista med ✓/pågår/kommande)
   ```
   Ingen "Starta steg"-knapp i kompaktvyn (arbetet fortsätter i chatten); i den
   utfällda listan får varje rad en liten knapp "Gå till" som skickar
   `ui/message` `Gå till steg {N} i "{titel}": {etikett}.`
3. **Utforska** – inget `current_step` (arbetsflöde eller samling): kompakt
   radlista, en rad per mall/steg: fet etikett, en rad syfte/intro (ellips), `›`.
   Hela raden är en knapp som skickar
   - arbetsflöde: `Starta "{paket}" från steg {N}: {etikett}.`
   - samling: `Använd mallen "{titel}" från paketet "{paket}".`
   Rubrik: `{package.title}` + märke `Arbetsflöde · Y steg` / `Samling · Y mallar`.

Stegetikett = `step_title` utan inledande "N. " (regex `^\s*\d+\.\s+`), annars
mallens `title`. `current_step` utanför 1..Y hanteras redan av servern
(`invalid_current_step`). `package_not_found` → "Paketet hittades inte." plus
knappen "Visa alla paket" (`ui/message` "Visa alla paket i Promptbanken.").

## 3. Paketkorten (`package-cards.html`)

- Visa de första **5** paketen (serverns ordning). Om fler finns: knapp
  `Visa fler ({N})` som visar resten i samma vy (lokalt, inget nytt anrop).
  Filtren (Alla/Arbetsflöden/Samlingar) gäller hela listan; gränsen på 5 gäller
  per filtrerad lista.
- **Layout:** bredd < 480 px → lodrät radlista (ikon, titel, en rad sammanfattning,
  typmärke, `›`; hela raden är "Öppna"). Bredd ≥ 480 px → kort i karusell där
  varje kort är ~85 % av bredden (`flex: 0 0 85%`, max 280 px) så att nästa kort
  syns som tydlig kant; höjd efter innehåll (`align-items: flex-start`), inget
  utsträckt tomrum.
- `audience_label` visas inte när den är lika med titeln (skiftlägesokänsligt).
- Namngivna färger och ikoner från katalogen mappas via fasta listor i
  `bridge.js`:
  - färger: `blue, indigo, violet, purple, pink, red, orange, amber, yellow,
    lime, green, emerald, teal, cyan, sky, slate, gray` → fasta hexvärden;
    okänt värde → genererad färg (som idag).
  - ikoner: `message, image, library, sparkles, chart, calendar, check, compass,
    document, lightbulb, people, shield, target, workflow` → fasta unicode-tecken;
    okänt värde → typikon (som idag). Inga fria värden når DOM:en som annat än
    `textContent`/hex.

## 4. Routing först (modellinstruktioner)

- `get_client_routing_instructions` (fri text, ingen kontraktsändring) får ett
  avsnitt "Routing först" på svenska:
  - Tydligt behov → `search_templates` → `get_template` på bästa träffen →
    ställ mallens första arbetsfråga direkt. Visa inte paketkort.
  - Osäker routing → nämn 2–3 alternativ i text och låt användaren välja.
  - Användaren vill utforska ("vad finns för chefer", "vilka arbetsflöden finns")
    → `recommend_packages` / `list_packages` (paketkort).
  - I ett aktivt arbetsflöde → `list_package_prompts` med `current_step` för
    orientering, sedan `get_template` för stegets text; upprepa inte mallens
    innehåll i text när widgeten visar det.
  - Efter `get_template`: sammanfatta inte mallen; gå direkt till första frågan.
- `recommend_packages` beskrivning: lägg till "Present the top 3–5 first; the
  rest only if the user asks for more."
- `get_template` beskrivning: lägg till "The client shows a compact 'in use' line;
  do not restate the template — continue with its first question."

## 5. Datafixar (server)

- **Bug 1 – `template_count`:** räknas från paketets faktiska medlemmar
  (samma källa som `list_package_prompts`), inte från mallarnas primära område.
  Implementeras i `_recommend_packages_payload` via katalogens paketmedlemskap
  (`_catalog_template_packages` eller motsvarande), så att
  `recommend_packages.template_count == len(list_package_prompts.prompts)`.
- **Bug 2 – område för mallar i flera paket:** `get_template` och
  `search_templates`-sammanfattningar får fältet `packages`: lista med
  `{slug, title, package_type}` för alla paket mallen ingår i (sorterad:
  arbetsflöden först, sedan titel). `area` behålls oförändrat för
  bakåtkompatibilitet men dokumenteras som "primärt paket". Mallvyn visar inget
  område.

## Test

- Pytest: `template_count` = antal medlemmar (fixture med mall i två paket);
  `packages` finns och är sorterad; routing-instruktionerna innehåller "Routing
  först"; beskrivningarna innehåller de nya meningarna.
- Widget-statiska tester (befintliga) gäller fortfarande (inga förbjudna tokens,
  ≤ 30 720 byte).
- Playwright i testvärden: aktiv-raden (standard, utfälld, felläge); stegvisarens
  tre lägen (arbetsläge med steg 2/6 och sista steget, utforska för arbetsflöde och
  samling, instruktionsladdning); paketkort med 18 paket (5 + "Visa fler"),
  360 px (radlista) och 420 px (karusell), namngiven färg/ikon, dold målgrupp.
- Dev: deploy + `check_live_open.py`, därefter Peters mobiltest i ChatGPT enligt
  acceptanskriterierna nedan.

## Acceptanskriterier (från handovern)

1. Tydligt behov går användarbehov → rätt arbetssätt → första arbetsfrågan med en
   enda användarinput.
2. Vid tydlig routing behöver användaren inte öppna paket eller välja mall.
3. En aktiverad mall renderas inte som ett nytt identiskt stort kort.
4. Aktiv mall/arbetsflöde har ett tydligt men kompakt aktivt läge.
5. Aktivt arbetsflöde visar namn, steg X av Y och aktuellt steg, utan
   biblioteksnavigation.
6. Mobil kräver inte långa serier av stora kort.
7. Rekommendationsvyn visar inte 18 likvärdiga primära val.
8. Routinglogiken och enkelheten från 1.2.2 bevaras.
